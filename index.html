        About the data

        • Station busyness — /crowding/{naptan}/Live: near-real-time busyness, refreshed by TfL about every 5 minutes, as a share of a per-station baseline that TfL sets (roughly the station’s usual busiest level, so values can exceed 100%). Crowding bands used here: Quiet < 25%, Moderately busy 25–50%, Busy 50–75%, Very busy ≥ 75%.
        • Typical profile — /crowding/{naptan}/{day}: the usual busyness for today’s day of week, in 15-minute bands.
        • Line status & next trains — /Line/{ids}/Status and /StopPoint/{naptan}/Arrivals.
        • Typical train loading — /StopPoint/{naptan}/Crowding/{line}, shown per direction relative to that direction’s busiest time slice, where TfL publishes it.
        • Quieter-time hint — looks ahead up to 3 hours in today’s typical profile for the first half-hour that drops a crowding band below the current reading.
        • Typical passenger flow — the passengerFlows values TfL returns with /StopPoint/{naptan}/Crowding/{line}, summed per 15 minutes. TfL doesn’t label the individual flows (for example entries vs interchanges), so treat it as relative busyness for that line at this station. TfL gives one profile with no day of the week; its morning and evening peaks suggest a weekday pattern.
        • Network status — /Line/Mode/tube,elizabeth-line,dlr,overground,tram/Status: the current status of every line, worst first, refreshed every 60 seconds.
        • Planned closures — /Line/{ids}/Status/{from}/to/{to} for today and the next 14 days. The list shows TfL’s planned works that are running now or start later, and any other change that hasn’t started yet. Live delays already under way are left out here because they’re in each line’s current status. TfL sometimes repeats an entry, so identical ones are shown once.
        • Whole line (the Show whole line button on Underground line cards) — /Line/{id}/Route/Sequence/all for the station order on each branch through this station, longest first, then /crowding/{naptan}/Live for each station on the chosen branch. That’s one request per station (16 for the Victoria line), so nothing loads until you press the button, requests go 3 at a time, readings are kept for 60 seconds, and the list isn’t refreshed automatically. Stations TfL doesn’t publish live crowding for show “No data”, not zero. It shows how busy each station is, not how full the trains are.
        • Lift faults — /Disruptions/Lifts/v2/, the feed behind tfl.gov.uk’s step-free information. It isn’t in the published API docs, so if it’s unavailable the dashboard simply doesn’t show lift status.
        • Station information (notices, facilities and Santander Cycles below) is off by default. Turn it on with the toggle next to Auto-refresh. While it’s off, the dashboard doesn’t request any of its data.
        • Station notices — /StopPoint/{id}/Disruption?getFamily=true&flattenResponse=true for the station and its child stations. TfL repeats a notice once per mode, so repeats with the same text and start time are shown once. Notices whose end date has passed are hidden.
        • Facilities — the Facility entries in /StopPoint/{id}, shown per network at interchanges. These are TfL’s static listings and may be out of date. For example, King’s Cross lists “0” help points. When several stations at an interchange list identical figures (as at Stratford), they are shown once.
        • Santander Cycles nearby — the docks TfL lists as NearestPlaces for the station, with live bikes, e-bikes and free docks from /Occupancy/BikePoints/{ids}. They are ranked by straight-line distance from /Place?type=BikePoint (not walking distance), and the nearest 5 are shown.
        • *Boarding estimate is this dashboard’s own estimate of whether you’ll get on the first train, per direction. It uses TfL’s typical train-loading scores (0–6, where 6 is full): how full trains usually leave this station, and how full they arrive from the previous station on the route (/Line/{id}/Route/Sequence/all). If a train starts here in that direction, for example the Waterloo & City line at Waterloo or Bank, it arrives empty. It assumes about 30% of arriving passengers get off. It then scales for how much busier the station is than usual, and for disruption or a long wait for the next train. TfL doesn’t publish platform queues or live train loads, so treat it as a rough guide.
        • *Platform outlook (shown when there’s no loading data for a line) is an estimate made by this dashboard, not a TfL figure: the station’s live level, raised a step for severe disruption, part of a step for minor delays, and a little when the next train is 8+ minutes away.

        About the SWR tab
        • Each section says where its data comes from in its own “About this data”. Most of it is from South Western Railway’s live train information and from National Rail’s live departures via Huxley2, a community-run wrapper. Neither is an official, documented API, so either may stop working without notice.
        • Station list — SWR’s own list of its stations (/api/swrstations on southwesternrailway.com), matched to TfL’s stops on the South Western Railway line by location and name, so stations TfL also covers (Waterloo, Vauxhall, Clapham Junction, Wimbledon, Richmond) can open in the TfL tab. The Isle of Wight’s Island Line stations have no TfL stop.
        • Nothing on this tab is requested until you open it, and it refreshes every 60 seconds only while it’s showing. The TfL tab pauses its own refresh while this tab is showing.

        Settings

        The API works without a key at a lower rate limit. A free key from the TfL API portal raises it. The key is stored only in this browser.
